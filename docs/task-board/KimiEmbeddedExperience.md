# Kimi 产品内调用体验

用户最新要求：必要时把 Kimi 的生成调用内嵌到 VideoCreator，用户在本产品查看进度、审核并接收最终结果，不需要安装或打开 Kimi、手工搬运文件。

## 实施边界

- 优先使用厂商允许的 API、MCP 或可随产品分发的 SDK/运行组件；集成组件只属于调用载体，不能据此声明图片、视频生成能力已通过。
- Kimi 官网创意插件的生成能力已有调研证据；插件对外接口、当前账号权益、后台调用和商业服务权限尚未核实。内嵌网页不能替代服务接口及实际生成验收。
- 如 Kimi 允许相关调用，在本产品内部封装提交、任务查询、下载校验、费用/额度对账、断线恢复；产物及关联音频、文本和语义信息落到安装实例。
- 如该能力没有合适的外部调用接口，保留 Kimi 作为已验证范围内的策划/理解 Provider，图像、视频使用可直接调用的专用 Provider。前台五步及 Portal API/MCP 入口保持统一。
- 官方订阅能力使用本产品服务凭证与权益；个人 Kimi 会员不能直接作为全部订阅用户共享的资源。

## 分工与当前证据

集成角色负责客户端/SDK/运行环境打包及载体；Agent/媒体负责具体生成 Provider 与真实产物；架构负责能力契约和官方准入。每项能力独立标记已验证、未验证、不可用，不将 SDK 安装成功当成生图或生视频成功。

I61 已完成修正后的 Kosong、PyKAOS、CLI、SDK 四组件真实构建及校验，生产依赖图仍在准备；这些构建结果尚不能证明 Kimi 图片/视频生成接口可用。本要求不授权新增收费试验、重置既有预算或使用未允许的内部接口。
